`facturas` es el SDK de TypeScript para facturar con ARCA, ex AFIP. Emitís
facturas, notas de crédito y notas de débito con CAE, y consultás el Padrón,
sin escribir SOAP ni calcular el IVA a mano. Lo usamos en producción en
[La Pyme](https://lapyme.com.ar).

<CodeGroup>

```bash pnpm
pnpm add facturas
```

```bash npm
npm install facturas
```

</CodeGroup>

```typescript
import { createArcaClient } from "facturas";

const arca = createArcaClient();

const resultado = await arca.issue({
  issuer: "monotributo",
  salesPoint: 3,
  to: { condition: "consumidor_final" },
  items: [{ amount: 150_000 }], // ARS 1.500,00 en centavos
});

if (resultado.kind === "authorized") {
  console.log(resultado.voucher.cae, resultado.voucher.number);
}
```

El cliente lee el CUIT, el certificado, la clave y el entorno de las variables
`ARCA_*`. No hace falta base de datos ni ningún servicio externo para emitir.
Requiere Node.js 22 o posterior y es solo ESM. El
[inicio rápido](/getting-started/quickstart) te lleva de cero a la primera
factura en homologación.

## Qué devuelve `issue()`

Los resultados fiscales se devuelven, no se lanzan. `issue()` devuelve uno de
cuatro, y tu código tiene que tratar los cuatro. Los errores de input y de
configuración sí se lanzan, antes de escribir en ARCA, y están en
[Errores](/reference/errors).

| Resultado | Qué significa | Qué tenés que hacer |
| --- | --- | --- |
| `authorized` | ARCA autorizó el comprobante. | Guardá el número, el CAE, su vencimiento y el `qr` para imprimir. |
| `rejected` | ARCA rechazó el pedido de forma definitiva. | Revisá `issues`. No cambies el input ligado a la clave. |
| `indeterminate` | No se puede demostrar todavía si ARCA lo autorizó. | Conservá la evidencia y conciliá antes de reintentar. |
| `conflict` | El número reservado pertenece a otro comprobante. | Detené el flujo e investigá. |

`indeterminate` existe porque ARCA, a diferencia de Stripe, no recibe una clave
de idempotencia. Si la conexión se corta después del envío, nadie sabe si el
comprobante quedó emitido. `facturas` asocia una clave de tu aplicación a un
store compartido, y así un reintento recupera el número reservado en vez de
emitir una segunda factura. Está explicado en
[Evitar comprobantes duplicados](/guides/avoid-duplicates).

## Del primer comprobante a producción

<Steps>
  <Step title="Habilitá ARCA">
    Conseguí el certificado, autorizalo para Facturación Electrónica y habilitá un punto de venta. El CLI te guía y [Habilitación en ARCA](/getting-started/arca-setup) tiene cada pantalla.
  </Step>
  <Step title="Emití en homologación">
    Configurá las variables de entorno, corré `npx facturas check` y emití tu primera factura de prueba con el [inicio rápido](/getting-started/quickstart).
  </Step>
  <Step title="Pasá a producción">
    Sumá un store, claves de idempotencia y el tratamiento de cada resultado. La lista completa está en [Pasar a producción](/guides/production).
  </Step>
</Steps>

## Una API para emitir y recuperar

`issue()` emite facturas a partir de datos de tu negocio y `preview()` te
muestra el pedido antes de enviarlo. Para corregir un comprobante usá
`issueCreditNote()` o `issueDebitNote()`. Si una respuesta queda incierta,
`recover()` consulta la reserva sin emitir otra vez. Cada método, con sus
opciones y resultados, está en la referencia del [cliente](/reference/client).

Para mantenimiento, diagnósticos y consultas técnicas, la referencia documenta
los [módulos de transporte](/reference/arca-services) que usa el cliente por
debajo. La emisión normal siempre entra por los métodos de la fachada.
